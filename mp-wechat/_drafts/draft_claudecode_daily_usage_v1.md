## 一个踩坑经历

那会儿要给项目加一个功能：支持用户上传特定 zip 文件，Python 后台进行分析，需要支持异步任务和进度追踪。

那时候我就意识到：**没想清楚就动手，等于白忙活。**

---

## Plan Mode 是什么？

简单说，就是让 Claude Code 在写代码之前，先制定一个完整的执行计划。

你可以把它理解为：施工之前，先画好图纸。

---

## 怎么用？

两步搞定：

1. 在 Claude Code 里按 `Shift+Tab`，或者直接说"进入 plan mode"
2. 描述你的需求

比如：

```
进入 plan mode，帮我设计一个 zip 文件上传分析功能，
Python 后台分析，需要支持异步任务和进度追踪。
```

然后你就可以喝咖啡去了。

## 它生成的计划什么样？

还是用上面的例子，这是它生成的计划（简化版）：

```markdown
# ZIP 文件上传分析功能实现计划

## 需求理解
- 用户上传特定格式的 zip 文件
- Python 后台解压并分析文件内容
- 使用异步任务处理耗时操作
- 实时进度追踪
- 前端上传组件和进度显示

## 架构设计

### 后端部分
1. 创建 AnalysisTask 模型（id, user_id, file_path, status, progress, result）
2. 创建 FileAnalyzer 服务类处理分析逻辑
3. 实现 ZIP 解压和文件解析模块
4. 使用 Celery/Redis 处理异步任务
5. WebSocket 推送进度更新

### 前端部分
1. 添加文件上传组件
2. 创建进度条组件显示分析状态
3. 完成后展示分析结果

## 关键文件
- 后端：/services/file_analyzer.py, /models/analysis_task.py
- 前端：/components/FileUpload.vue, /components/ProgressBar.vue

## 执行步骤
1. 创建数据模型和迁移文件
2. 实现文件上传接口
3. 实现分析服务类
4. 集成 Celery 异步任务
5. 添加 WebSocket 进度推送
6. 前端组件开发和集成
7. 测试和优化
```

看到这个计划，我第一反应是：**这比我自己想得还全面。**

进度追踪、WebSocket 推送……这些我可能都会忽略的细节，它全想到了。

嘿嘿，有时候我会想，是不是我这个"老司机"反而不如它细致？

确认计划之后，Claude Code 就会按照计划一步步执行。如果有哪里不满意，直接改那个 markdown 文件就行。

## 为什么好用？

**最大的坑不是代码写错，而是方向搞错。**

Plan Mode 会在动手之前，先把思路理清楚。你可以在开始之前就发现方案行不通、设计有问题。

而且，Claude Code 最强的不是写代码，而是理解代码。Plan Mode 让它先分析你的代码库、理解你的架构，然后再设计解决方案。这比直接让它"瞎写"要好得多。

有了计划文件，你也能看到它打算怎么做、提前发现问题、调整执行顺序。这比它写了一堆代码，你再一个个改要高效得多。

---

## 我的使用经验

**什么时候用 Plan Mode？**

我的判断标准很简单：**超过 30 分钟的任务，就用。**

比如新功能开发、涉及多个文件的重构、不知道根因在哪里的 Bug 修复、需要分析瓶颈的性能优化……

简单的小改动就不用了，直接干更高效。

**几个小技巧：**

- 它问问题时别嫌烦，认真回答——这些问题往往是你没考虑到的细节
- 计划生成后仔细读一遍，看看方案是否符合需求、有没有遗漏、执行顺序是否合理
- 计划文件是可以编辑的，觉得哪个步骤不对直接改就行
- 特别复杂的任务，可以加上"ultrathink"，让它花更多时间思考

## 效率对比

这个没法给精确数字，但我可以说说感受。

**不用 Plan Mode 时：**经常写到一半发现方向错了，很多时候要返工，整体感觉很"慌"。

**用了之后：**动手前就知道要做什么，很少返工，考虑问题更全面，整体感觉很"稳"。

如果非要说一个数字，我觉得复杂任务的整体效率至少提升了 2-3 倍。

更重要的是心态变了。以前是"试试看能不能成"，现在是"按计划执行即可"。

## 小结

如果你也在用 Claude Code，但还没有试过 Plan Mode，强烈建议你试试。

Plan Mode 最大的价值，不是让 Claude Code 写代码更快，而是让整个开发过程**更可控、更可预测、更少返工**。

这比单纯的"快"要重要得多。
