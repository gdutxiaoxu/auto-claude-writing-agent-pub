# Claude Code 的 Skills：不只是规则，而是"懒加载"的知识

哈喽，大家好，我是徐公。

今天说个很多人没注意到，但用了就回不去的功能：**Skills**。

说实话，刚开始我以为这跟 CLAUDE.md、知识库没什么区别。用了一段时间才发现，**它解决了一个很多人没意识到的问题：token 浪费。**

---

## 问题一：每次都要说一遍规则

用 Claude Code 的时候，你有没有遇到过这种情况：

每次让它生成 commit message，它都写得不合你规范。每次你都要说：
- 标题要控制在 50 字以内
- 用现在时态
- 说明"做了什么"和"为什么"

一次两次还好，次数多了真的很烦。

---

## 问题二：规则太多，上下文爆炸

CLAUDE.md 我也写过，但它有个问题：**所有内容都会加载到每个对话的上下文里。**

一开始还好，规则多了以后：
- 你的 CLAUDE.md 有 500 行
- 每次对话都要把这 500 行加载进去
- 你只是想问个简单问题，却要消耗一大堆 token

更烦的是，知识库也是这样。你把文档放进去，Claude 会把相关内容加载到上下文。但"相关"这个判断有时候不太准，该加载的没加载，不该加载的加载了一堆。

---

## Skills 的两个独特设计

Skills 跟 CLAUDE.md、知识库不一样，它有两个关键设计：

### 1. 只加载元数据

Skills 启动时，**只加载 name 和 description**。

你有一百个 Skills 也没关系，Claude 只需要读取一百行 description，就能判断什么时候用哪个 Skill。具体的规则内容，只有在 Skill 被触发时才加载。

这意味着什么？

- 你的 100 个 Skills，每个 200 行规则
- 普通方式：每次对话都要把 20000 行加载到上下文
- Skills 方式：只加载 100 行 description，按需加载规则内容

token 消耗完全不是一个量级。

### 2. 渐进式加载

Skills 支持把详细文档、示例、脚本放在单独的文件里。SKILL.md 只保留核心内容，其他文件用链接引用。

```markdown
## 快速开始
[核心规则，20行]

## 更多资源
- 详细文档见 [reference.md](reference.md)  # 200行，按需加载
- 使用示例见 [examples.md](examples.md)    # 300行，按需加载
```

Claude 不会一下子把所有文件都读进来，而是需要时才加载。

你只是想问个简单问题，它只用那 20 行核心规则就够了。
你遇到复杂场景，它才会去读那 500 行详细文档。

## 一个简单例子

### 第一步：创建文件夹

在 `~/.claude/skills/` 下创建一个文件夹：

```
~/.claude/skills/commit-helper/
```

### 第二步：创建 SKILL.md

在这个文件夹里创建 `SKILL.md`：

```markdown
---
name: commit-helper
description: 生成符合规范的 commit message。当用户提到 git、commit、提交代码时自动使用。
---

# Commit Message 规范

## 格式要求
- 标题：50 字以内，现在时态
- 说明"做了什么"和"为什么"
- 不要写"如何实现"

## 好的例子
- feat: 添加用户头像上传功能
- fix: 修复登录时 token 过期问题
- docs: 更新 API 文档

## 不好的例子
- fix bug（太笼统）
- 修改 login 函数逻辑（写了"如何"）
- add feature（没说明是什么功能）
```

### 第三步：完成

就这？

对，就这。

现在你只要说"帮我写个 commit message"，Claude 就会按照你的规范来生成。

而且，只有当你真的提到 commit 时，这个 Skill 才会被加载。其他对话根本不会占用你的上下文。

---

## 对比：Skills vs CLAUDE.md vs 知识库

| 特性 | Skills | CLAUDE.md | 知识库 |
|------|--------|-----------|--------|
| 触发方式 | Claude 自动判断 | 每次对话都加载 | 搜索相关内容 |
| 加载内容 | 只加载元数据 + 按需加载 | 全部加载 | 搜索结果加载 |
| Token 消耗 | 极低 | 高（规则多时） | 中等 |
| 适用场景 | 特定任务的标准操作 | 项目全局规则 | 通用知识查询 |

打个比方：
- **CLAUDE.md** 是把所有规则都写在黑板上，每次上课都要擦掉重写
- **知识库**是图书馆，你要什么书它帮你找，但有时候找不准
- **Skills** 是卡片目录，你只需要看一眼目录就知道有什么书，需要时再取

## Skills 的好处

### 1. 不用重复说

写一次，反复用。以后再也不用每次都解释一遍规则。

### 2. 节省 token

只加载元数据，按需加载详细内容。规则再多也不会影响日常对话。

### 3. 团队规范统一

把 Skill 提交到项目仓库，整个团队都能用。所有人生成的 commit message 格式都一样。

### 4. 自动触发

你不需要手动调用，Claude 会根据你的请求自动选择合适的 Skill。

### 5. 可以限制权限

有些 Skill 可以设置为"只读"，比如代码审查。Claude 只能看代码，不能改。

---

## 什么时候用 Skills

**用 Skills：**需要反复执行的"标准操作"（代码审查、文档生成、commit 格式）、团队规范需要统一、规则内容较长希望按需加载

**用 Slash Commands：**一次性操作（`/deploy staging`）、需要手动触发的命令

**用 CLAUDE.md：**项目全局规则（TypeScript 严格模式、目录结构）

**用知识库：**通用知识查询、技术文档参考

---

## 小结

Skills 最大的价值，不只是"写一次反复用"，而是**通过元数据索引 + 渐进式加载，解决了规则多了以后上下文爆炸的问题。**

规则少的时候，CLAUDE.md、Skills、知识库区别不大。

但规则多了以后，Skills 的优势就出来了：你不用担心规则太多影响性能，因为它们大部分时间都"躺"在磁盘上，只有被需要时才会醒来。

写一次，反复用，还省 token。这种感觉很爽。
