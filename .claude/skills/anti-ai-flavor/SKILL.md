# 去除 AI 味道写作指南

> **适用范围**：所有写作任务（公众号、文章、文档等）
> **触发时机**：初稿完成后、用户要求"降AI味"或"更像人写的"时

---

## 什么是 AI 味道

AI 味道是指文章中显露出的"非人类"特征，包括：
- 套话连接词
- 形容词堆砌
- 过于工整的结构
- 缺乏个人观点
- 套路化表达

---

## 快速识别：AI 味道特征清单

### 1. 套话连接词 ❌

| AI 味 | 人味 |
|-------|------|
| "在...背景下" | 删除，直接说事 |
| "成功地将...与...深度融合" | "把...和...结合起来" |
| "完美解决" | "解决了"或"搞定" |
| "全新的技术路径" | "新做法" |
| "前所未有的简单" | "简单多了" |
| "显著优势" | "优势" |
| "大幅降低" | "不用..." |
| "从实用性角度看" | 删除，直接说 |
| "总而言之" | "总的来说"或删除 |
| "值得注意的是" | 删除，直接说重点 |

### 2. 形容词堆砌 ❌

**问题示例**：
```
browser-use 是一个功能强大、性能卓越、易于使用的开源工具
```

**修改后**：
```
browser-use 是个开源工具，挺好用的。
```

**原则**：一个词能说清楚的，不要用三个词。

### 3. 套路化表达 ❌

| AI 味 | 人味 |
|-------|------|
| "图示说明：" | 直接说明图片内容 |
| "预期输出：" | "跑一下会..." |
| "综上所述：" | "总的来说"或删除 |
| "首先...其次...最后..." | 删除，直接讲 |
| "一方面...另一方面..." | 删除，直接讲 |

### 4. 过于工整的段落结构 ❌

**AI 味表现**：
- 每段长度差不多
- 段落开头总是相似的结构
- 没有长短变化

**人味特征**：
- 段落有长有短
- 有些段落就一句话
- 节奏有变化

### 5. 缺乏个人观点 ❌

**AI 味**：全篇客观描述，没有"我认为"、"我觉得"

**人味**：加入个人判断
- "我实测下来，确实差距挺明显"
- "我试了下，基本属实"
- "最后说句实话"

## 修改技巧

### 技巧 1：删除套话连接词

**操作**：
1. 搜索文章中的套话词
2. 删除它们
3. 看看意思是否还在

**示例**：

**原文**：
```
在当今AI技术飞速发展的时代，browser-use 成功地将大语言模型的推理能力与浏览器自动化技术深度融合。
```

**修改后**：
```
browser-use 把大模型和浏览器自动化结合起来了。
```

### 技巧 2：把书面语改成口语

**原则**：像说话一样写

| 书面语 | 口语 |
|-------|------|
| "进行操作" | 直接说具体动作 |
| "通过XX方式" | "用..." |
| "实现XX目标" | "..." |
| "相关工作" | 具体说什么工作 |
| "相关领域" | 具体说什么领域 |

### 技巧 3：加入个人观点

**操作**：
1. 在描述完功能后，加一句个人判断
2. 用"我"开头
3. 说实话，别说套话

**示例**：

**原文**：
```
官方推出的 ChatBrowserUse 模型在完成网页任务时比通用模型快 3-5 倍。
```

**修改后**：
```
官方还专门优化了一个 ChatBrowserUse 模型，号称比通用模型快 3-5 倍。我实测下来，确实差距挺明显的。
```

### 技巧 4：简化技术描述

**原则**：能用一句话说清楚，绝不用两句话

**原文**：
```
browser-use 采用分层架构设计，核心包含浏览器控制层、页面解析层、元素识别层、决策规划层和工具集成层五个主要模块。
```

**修改后**：
```
技术栈其实不复杂，但组合得挺巧妙。底层用的是 Playwright，中间加了一层页面解析，最核心的是元素识别层——这里用了两种策略：传统的 DOM 查询 + AI 语义理解。
```

### 技巧 5：让段落有节奏变化

**检查方法**：
1. 标记每句话的字数
2. 看是否有变化
3. 如果连续 5 句都是差不多长度，需要调整

**示例**：

**单调版本**：
```
browser-use 是一个开源项目。(11字)
它能让 AI 控制浏览器。(11字)
这个项目有 7.6 万星。(10字)
主要面向开发者和测试人员。(12字)
```

**有节奏版本**：
```
browser-use 是个开源项目。(11字)
简单说，它让 AI 能像人一样操控浏览器。(18字)
目前 7.6 万星。(7字)
```

### 技巧 6：结尾要像人话

**AI 味结尾**：
```
综上所述，browser-use 是当前 GitHub 上最具创新性的 AI 工具之一，值得开发者深入探索和尝试。
```

**人味结尾**：
```
最后说句实话：这类"AI + 自动化"的工具，以后会是 RPA 的主流方向。browser-use 算是这波浪潮里做得比较早、也比较好的一个。如果你有重复性的网页操作要自动化，值得试试。
```

## 三遍修改法

### 第一遍：删除套话

- 搜索并删除所有套话连接词
- 删除"图示说明"、"预期输出"等套路表达
- 删除过于正式的连接词

### 第二遍：简化表达

- 把书面语改成口语
- 简化技术描述
- 删除形容词堆砌

### 第三遍：加入人味

- 加入个人观点和判断
- 调整句子节奏
- 让段落有长短变化
- 优化开头和结尾

---

## 检查清单

修改完成后，检查以下问题：

- [ ] 没有套话连接词（"在...背景下"、"成功地将"等）
- [ ] 没有形容词堆砌
- [ ] 没有套路化表达（"图示说明"、"预期输出"等）
- [ ] 有个人观点（"我认为"、"我试了下"等）
- [ ] 句子长度有变化
- [ ] 段落长度有变化
- [ ] 结尾像人话

## 对比示例

### 示例 1：项目介绍

**AI 味版本**：
```
browser-use 是一个让 AI 代理能够像人类一样操控浏览器的开源项目，它成功地将大语言模型的推理能力与浏览器自动化技术深度融合。在传统浏览器自动化工具主要依赖预定义规则和硬编码脚本的背景下，browser-use 开辟了一条全新的技术路径。
```

**人味版本**：
```
这几天刷 GitHub，看到一个项目让我眼前一亮——browser-use。

简单说，它让 AI 能够像人一样操控浏览器。听起来没什么特别的？但当你真正上手之后，会发现这东西解决了一个很实际的问题：AI 模型再聪明，也没法和网页交互。而 browser-use 填上了这个坑。
```

### 示例 2：功能描述

**AI 味版本**：
```
**智能网页元素识别与定位**: browser-use 能够自动分析网页的 DOM 结构，识别可交互的元素（按钮、输入框、链接等），并通过多种策略（文本匹配、语义理解、视觉特征）精确定位目标元素，无需手动编写 CSS 选择器或 XPath。
```

**人味版本**：
```
### 不用写选择器了

用过 Selenium 或 Playwright 的都知道，定位页面元素是最头疼的。CSS 选择器、XPath 写一堆，页面一改就全废。

browser-use 的做法是：让 AI 自己理解页面结构，找到它要操作的元素。按钮、输入框、链接，它都能认出来，而且是根据语义和内容来判断，不是靠硬编码的路径。
```

### 示例 3：技术描述

**AI 味版本**：
```
browser-use 采用分层架构设计，核心包含浏览器控制层、页面解析层、元素识别层、决策规划层和工具集成层五个主要模块。
```

**人味版本**：
```
技术栈其实不复杂，但组合得挺巧妙。底层用的是 Playwright，中间加了一层页面解析，把 HTML 转成结构化的 DOM 树。最核心的是元素识别层——这里用了两种策略：传统的 DOM 查询 + AI 语义理解。
```

### 示例 4：总结

**AI 味版本**：
```
browser-use 的核心优势在于将 AI 的理解能力与浏览器自动化完美结合，让复杂任务的自动化变得前所未有的简单。该项目是当前 GitHub 上最具创新性的 AI 工具之一，值得开发者深入探索和尝试。
```

**人味版本**：
```
browser-use 解决了一个实际问题：让 AI 能真正和网页交互。和 Selenium、Playwright 这些传统工具比，最大的区别是不用研究页面结构，不用写选择器，你告诉它要干什么，剩下的 AI 自己搞定。

最后说句实话：这类"AI + 自动化"的工具，以后会是 RPA 的主流方向。browser-use 算是这波浪潮里做得比较早、也比较好的一个。如果你有重复性的网页操作要自动化，值得试试。
```

## 核心原则

1. **像说话一样写**：口语化，自然
2. **有个人观点**：加入"我"的判断
3. **简洁**：删除不必要的内容
4. **有变化**：句子、段落要有长短变化
