# 写作任务类型判断

## 适用场景

当用户提出任何与写作相关的请求时，首先使用此skill判断任务类型。

## 六种任务类型

### A. 新写作任务（有完整brief）

**特征**：
- 用户提供了明确的写作需求
- 已有brief文档或需求足够完整

**流程**：执行对应平台的完整写作流程

### B. 新写作任务（无brief只有需求）

**特征**：
- 有写作意图，但信息不完整
- 需要先与用户确认需求

**流程**：
1. 与用户确认写作需求
2. 创建brief文档保存到 `_briefs/`
3. 然后按类型A执行

### C. 修改已有文章

**特征**：
- 用户提供了现有文章路径
- 明确说明修改要求

**流程**：
1. 读取原文
2. 理解修改需求
3. 执行修改
4. 走审校流程（至少第二遍：风格审校）

### D. 文章审校/降AI味

**特征**：
- 用户明确要求审校
- 用户明确要求降AI味
- 文章内容已完成，只需优化

**流程**：
1. 第一遍：内容审校（逻辑、事实、结构）
2. 第二遍：风格审校（降AI味）⭐⭐⭐
3. 第三遍：细节打磨（标点、排版、节奏）

### E. 快速咨询

**特征**：
- 简单问题，不需要写作
- 咨询类问题
- 用户明确说"快速问一下"

**流程**：直接回答问题，不创建任何文档，不走任何流程

### F. 平台规则咨询

**特征**：
- 用户询问某个平台的规则
- 用户询问某个步骤的详细操作

**流程**：查阅对应平台的规则文档

## 判断示例

- "帮我写一篇关于Claude Code的文章" → **类型A**
- "我想写一篇关于AI换脸的文章" → **类型B**
- "修改 _drafts/xxx.md 这篇文章" → **类型C**
- "这篇文章AI味太重，帮我优化一下" → **类型D**
- "选题讨论是第几步？" → **类型E**

## 特殊情况处理

- 用户明确要求跳过步骤：可以遵循，但必须提醒风险
- 任务类型模糊：Think Aloud说明可能性，询问用户确认
